# Runtime contract v1 — proposed, not ratified
Cycle 02, Core 01. Source-only. This contract supplements the earlier FEidolonGameplayEvent; no destructive migration. Studio dependencies v1 and actual PR APIs reviewed.

## Authority and lifetime
| Property | M1 authority | Intended campaign authority |
|---|---|---|
| Health, stamina, defeat | legacy AEidolonCharacter and AEidolonArenaEnemy | Combat component only, after coordinated replacement |
| Movement, camera, input | Core / existing pawn | Core |
| NPC intent | AI proposal only | AI proposes, Combat validates and executes |
| XP, wallet, inventory, rank | legacy campaign where currently present | RPG rules evaluated inside Save transaction |
| Quest cursor, rewards, reality, flags | legacy campaign until migrated | Save atomic transaction with Quest/RPG/Reality rules |
| UI | read-only capture | read-only snapshot after commit |
| preferences | Core local slot | Core local slot, independent of campaign |
World subsystem observations are synchronous, game-thread, authority-side, bounded at 4096 unique IDs per world, reset at teardown. No tick or persistence. Reentrant publish rejected; caller must defer explicitly. A full ledger fails closed, never evicts to admit duplicates. No campaign write or reward handler may subscribe to M1 observations. Engine world lifecycle tests remain pending.

## Envelope
FEidolonRuntimeEvent: schema 1; GUID occurrence ID; typed Kind and Domain; source/target stable instance IDs; semantic ID; chapter; quest; expected revision. Sandbox chapter 0, no quest, revision -1; campaign chapter 1..26, revision >=0, objective requires quest. Both source and target required. ID grammar lowercase ASCII snake_case, 1..128, no repeated or edge underscore. Semantic keys distinguish event vocabulary from occurrence IDs. Unknown enum values and versions rejected. Exact duplicate returns Duplicate; same GUID with any changed field returns Conflict. Producers allocate GUID once at authoritative transition, never per retry. Durable IDs and canonical entity mappings must survive reload; M1 IDs are session-only. For campaign, Save must compare GUID plus immutable payload and atomically persist receipt, revision, quest progress, inventory and reality; this is a requirement, not implemented by Core. Save must check duplicate/conflict before optimistic revision mismatch, so an acknowledged retry succeeds idempotently. Revision denotes the pre-transaction state. Reject stale new events without mutation. Publish committed snapshots only after successful commit. Never infer semantic event from UI text or an AI intent.

## API comparison and concrete adapters
- 02 Game #8: UEidolonCombatComponent OnImpact(AActor*,int32), OnDeath() lack stable source/target and contextual occurrence ID. Spawn owner assigns stable instance IDs; Combat must supply actual killer and outcome. M1 legacy pawn remains sole authority. Do not attach Combat alongside legacy damage. Example: confirmed death producer calls UEidolonM1Adapter::ObserveDeath(existingGuid, "m1_player", "m1_enemy_01", false). Current wired producer is player defeat only; unknown attacker is explicit aggregate placeholder, not a durable identity.
- 03 Game #10: EidolonRpg::Wallet/Bag/Catalog and Buy/Sell/Craft pure rules. Save owns candidate wallet and commits only on successful validation; no second wallet in Core. Dotted catalog IDs require explicit aliases, no automatic case folding. RewardCommitted is a post-commit fact, not a reward command.
- 04 Game #9: UEidolonNPCBrainComponent::Evaluate returns FName; OnIntentChanged is proposal, not proof of attack/death. Translate known intent names only after registry review; never award XP from intent.
- 05 Game #11: FEidolonHUDSnapshot Capture(APlayerController*) reads legacy pawn/campaign. M1 adapter Capture returns health/stamina/defeat with availability; missing mana remains unavailable. Example UI reads pawn FindComponentByClass<UEidolonM1Adapter>()->Capture() after null check; no mutation. Rebind on pawn replacement.
- 06 Game #12: FEidolonRealityState::Apply(FName Event,int32 Chapter,int32 ExpectedRevision) uses semantic FName AppliedEvents, not occurrence GUID. Do not pass GUID as semantic ID. Save needs separate durable GUID receipt map and atomic candidate state; semantic once-only reality transitions remain separate. No direct calls from Core until transaction API agreed.
- 08 Game #23: EidolonQuest::FEvent has FName Id/Type/Source/Target/Quest plus Chapter. EidolonProjectQuestEvent projects validated campaign QuestObjective only, GUID digits to FName; then assign fields to FEvent and invoke Apply on candidate progress. Example guild_register in mq_02 chapter 2. Raw EnemyDefeated is rejected; Quest authority validates contextual fact and issues distinct objective occurrence ID with retry stability. Save must retain causal mapping to prevent repeat derivation. No direct include of unmerged Quest header.
